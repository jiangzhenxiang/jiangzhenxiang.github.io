# 公众号排版发布

把已经确认的文章变成可在手机浏览器预览、可分别复制标题与富文本正文的公众号发布页。默认只生成预览；只有用户明确说“发布、提交、上传到 GitHub”时才修改远程仓库。

## 用户环境

- GitHub 仓库：`jiangzhenxiang/jiangzhenxiang.github.io`
- 默认分支：先读取仓库确认，不写死；已知通常为 `master`
- GitHub Pages 根地址：`https://jiangzhenxiang.github.io/`
- 推荐路径：`wechat/<series-slug>-<NN>/index.html`
- 图片路径：`wechat/<series-slug>-<NN>/assets/`

不要修改博客首页、Jekyll 配置或既有文章，除非用户明确要求。

## 工作流

1. 确认文章内容和标题。未经要求，不实质改写文章；发现事实风险时先核对。
2. 根据内容选择视觉风格。人物故事、观点和叙事默认使用克制的杂志风；不要使用廉价霓虹科技风。
3. 短文通常使用 1–2 张插图：开头建立场景，中段承接关键转折。优先使用 GPT Image 生成统一风格的无字横图；需要真实照片时再搜索可合法使用的来源。
4. 生成单页 HTML：页面工具栏与复制内容分离，正文内部全部使用内联样式。
5. 本地检查 HTML、图片路径、按钮和移动端布局。
6. 用户明确授权发布后，读取远程最新分支头，基于最新提交上传 HTML 和图片，使用非强制快进更新，避免覆盖并发修改。
7. 发布后重新读取远程文件，确认 HTML 引用了真实存在的图片，并返回 Pages 地址与提交 SHA。

## 默认排版

人物故事系列默认使用：

- 主文字：`#2B2B2B`
- 深空蓝：`#243247`
- 火星橙红：`#D95436`
- 暖灰卡片：`#F6F4F0`
- 正文：16px，行高 1.9
- 内容最大宽度：677px
- 圆角不超过 8px
- 每段手机端约 2–4 行，段间距约 18px
- 强调色只用于系列标识、转折句和少量金句，不大面积染色

其他题材可调整颜色，但保持克制、清晰、适合手机阅读。

## 插图规则

- 公众号短文默认不超过两张正文图，除非内容确实需要。
- 正文图优先使用 3:2 横图，无文字、无水印。
- 同一系列保持相同媒介、色板和质感。
- 生成图不得冒充真实历史照片；图注标明“GPT Image 生成”。
- 项目图片压缩到最长边约 1200px，JPEG 质量约 85；在清晰可读前提下控制加载体积。
- HTML 中使用完整的 GitHub Pages 绝对图片地址，避免复制到公众号后因相对路径失效。
- `alt` 文本描述画面信息，不堆关键词。

## HTML 与复制要求

- 页面提供“复制标题”和“复制排版正文”两个按钮，因为公众号标题栏与正文区分开。
- 富文本复制优先使用 Clipboard API，同时提供 `text/html` 和 `text/plain`。
- 兼容路径使用 Range 选中正文并执行复制。
- 复制目标只能是文章正文，不得包含工具栏、按钮或操作提示。
- 正文中不使用外部 CSS、网页字体、CSS 变量、脚本或交互控件。
- 图片、颜色、字号、边距和卡片样式全部写成内联样式。
- 页面本身响应式，手机端不得横向滚动。

## 发布安全与验证

- GitHub 发布属于外部写操作，每一次都需要用户在当次请求中明确授权。
- 发布前查询远程最新提交；不要假定上一次提交仍是分支头。
- 禁止强制更新分支，禁止删除或覆盖无关文件。
- 如果发生并发更新，重新基于最新提交构建，不覆盖他人的新内容。
- 校验 HTML 能被解析，图片文件是有效 JPEG/PNG，并确认远程路径存在。
- GitHub Pages 更新可能延迟；仓库文件已成功不等于线上页面已立即刷新，分别说明两种状态。

## 交付说明

完成后只需告诉用户：

- Pages 页面地址
- 插图数量和位置
- 使用方式：先复制标题，再复制排版正文
- 远程提交 SHA（若已发布）
- 未能验证的环节或手机编辑器可能清除富文本样式的限制
